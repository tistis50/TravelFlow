# TravelFlow — МДК 05.02

Учебное расширение исходного проекта: «Журнал фактических расходов по командировкам». Существующие страницы сохранены. Новый модуль работает с SQLite через локальный Python-сервер, а не с localStorage. Старые страницы пока остаются автономным прототипом с localStorage: в SQL-справочник перенесены три демонстрационные поездки № 2, 11 и 12 из исходного набора. Автоматической синхронизации старых страниц и справочника нет; журнал не заменяет старое поле фактических расходов и не обновляет старые отчёты.

## Запуск

1. Установить Python 3.10 или новее. Для приложения дополнительные библиотеки не требуются.
2. Распаковать папку проекта. Открыть терминал в ней.
3. Windows: `py -3 app.py`; Linux/macOS: `python3 app.py`.
4. Открыть в браузере `http://127.0.0.1:8000/`, выбрать «Журнал расходов».
5. Войти под одной из демонстрационных учётных записей:

| Логин | Пароль | Доступ |
|---|---|---|
| accountant | accountant-demo | Просмотр, добавление, изменение, фильтрация |
| admin | admin-demo | Всё перечисленное и удаление с подтверждением |

6. Выбрать поездку, категорию, сумму, дату, при необходимости комментарий. Нажать «Добавить расход». Для изменения использовать соответствующую кнопку. Для удаления войти администратором. Для остановки сервера нажать Ctrl+C в терминале.

Файл `travelflow.sqlite3` создаётся автоматически при первом запуске. Повторный запуск не очищает записи. Для просмотра готовой демонстрационной БД из папки evidence можно выполнить `python app.py --db ../evidence/tested.sqlite3` (сначала сделать копию этой БД, если нужны исходные результаты). Параметр `--port 8001` меняет порт. Не удаляйте БД, если необходимо сохранить данные.

## Структура

- `index.html` — исходный TravelFlow с добавленной ссылкой.
- `app.py` — HTTP-сервер, представления, проверка сессии и прав.
- `storage.py` — валидация и параметризованные запросы.
- `schema.sql` — таблицы trips и expenses, индекс и исходные ссылки на три поездки.
- `module.css` — оформление и адаптация нового интерфейса.
- `test_module.py` — предварительные HTTP/SQL-проверки на отдельной временной БД.

## Проверка

Приложение не требует сторонних библиотек. Для запуска тестов установите `python -m pip install requests beautifulsoup4`, затем `python test_module.py`. При необходимости используйте свободный порт: `python test_module.py --port 8766`. Дополнительный флаг `--capture` требует Playwright и Chromium; он автономно визуализирует ответы сервера, а не управляет живым сайтом в браузере. Проверки 05.02 не являются полным тестированием 05.03.

## Ограничения

Сервер слушает только 127.0.0.1. Демонстрационные пароли фиксированы в коде и предназначены только для учебного запуска. Это не промышленная аутентификация. Старые страницы не защищены новыми ролями; новая сессия относится только к журналу. Для реальной эксплуатации нужны общая серверная БД, синхронизация командировок, индивидуальные учётные записи с хешированием паролей, HTTPS, аудит изменений, резервное копирование и отдельные проверки доступа. Два контролируемых дефекта интерфейса оставлены для МДК 05.03; см. отдельный файл `CONTROLLED_DEFECTS.md`.

## Git и GitHub

В архиве сохранена папка `.git` с реальными локальными коммитами. После распаковки выполните `git log --oneline` и `git status`. На GitHub создайте пустой **приватный** репозиторий (не добавляя README и .gitignore автоматически). Проверьте исходный учебный HTML на наличие реальных персональных данных до публикации. Для отправки истории:

```
git remote add origin https://github.com/ВАШ_ЛОГИН/ВАШ_РЕПОЗИТОРИЙ.git
git push -u origin main
```

Авторизация выполняется самим владельцем аккаунта средствами Git/GitHub; не передавайте пароль или токен в переписке. Если origin уже существует, проверьте `git remote -v` и используйте `git remote set-url origin ...`. Ссылка на репозиторий в отчёте заполняется после реальной публикации. Отправка только в конце сохраняет локальную историю, но не подтверждает требование о публикации на GitHub по ходу разработки.
